# Whole-game visual direction and acceptance
The owner wants strong BTD6 influence across the whole visual language, not just map layouts: colorful rounded characters, recognizable silhouettes, strong outlines, controlled shading/ground shadows, progression in visible equipment, readable defenses/attacks, familiar tower-defense screen organization and attractive menus. Original cats, mice/rats, fish, map geometry and production UI assets. Static scenery, simple combat animation, NO sound.

## References and limitations
Read references/REFERENCE_GUIDE.md. Thirteen local image extracts are always available in the repo. It is a reference index, not 129 validated/offline assets. A label 'upgrade paths' is not evidence that its preview actually depicts an upgrade panel. Inspect actual loaded images. No extracted BTD6 sprites, screenshot fragments or reference library files in the production bundle.

## Bounded owner review before bulk production
Deliver in M2: a one-page palette/line-width/proportion/light-direction guide; one cat at base/tier-3/tier-5 with visible path differences; one ordinary rat plus Sneaky/Armored/Fortified variants; main HUD with shop/placement range and three upgrade paths; study screen; one actual playable map screenshot at desktop and touch size. The owner must approve the visual direction before multiplying this style across all towers/maps. Engine tests may continue while artwork awaits review. No claim of 'approved' without an actual owner response.

## Acceptance tests
At intended gameplay scale, identify tower type, enemy modifier and selected upgrade state without zooming. Distinguish status through shape/pattern as well as color. UI prices/buttons/targets remain readable with dense combat. Render no transparent-edge halos, clipped portraits, misaligned pivots, mismatched outline widths or missing sprites. Show valid/invalid placement and range, meaningful affordability states, cooldowns and actual functional controls. Comparison screenshots must be from the running game, not reference art or fabricated previews.
Each map needs its own original route, props, construction areas, thumbnail and consistent environment scale. Record actual geometry separately from decorative art. Every cat has complete shop portrait, idle/attack state and upgrade representations (layered equipment overlays are acceptable). Keep animation simple; no ambient leaf/water motion required.

## Implementation route
Keep original SVG/PNG/WebP assets and an asset manifest of ID, file, dimensions, anchor, footprint and states. Cache/rasterize for dense rendering. Canvas vectors are allowed ONLY when they meet the approved look; crude circles are development placeholders, not final delivery.
Canva/Higgsfield/Figma are optional only if available within the chosen Codex environment and useful at no additional charge. Free quotas/exports must be checked before depending on them. Original code-authored artwork is the reliable fallback, not automatic permission to reduce quality. Use one consistent approved design as a reference for later assets. Record origins/licenses of external production assets and do not purchase credits without owner permission.
