# Whisker Watch — Decision Register

## Purpose and status

This document records implementation ambiguities in the canonical [master specification](../WHISKER_WATCH_MASTER_PROMPT.md). It prepares the Codex workspace; it does not implement the game or approve a design.

**Every interpretation in the table is PROPOSED, not approved.** Preserve firm requirements unless a later explicit project instruction changes them. Resolve decisions at their listed gate, record the outcome in `DESIGN_STATE.md`, and update this register with the approving instruction and resulting behavior. Do not treat an unresolved proposal as permission to change the specification.

## Current scope and workflow

- The complete delivery target is **five main maps plus the Tutorial**, with the specified difficulties, cats, rats, study systems, and file saves. The original Tutorial-plus-Map-1 v1.0 remains an intermediate release milestone; maps 2–5 follow through the specified post-v1 map phases.
- The study-content pipeline is **notes/PDF source → external AI formatter or text extraction → structured JSON/CSV deck → in-game validation/import**. Direct reading of PDF, Word, or image files inside the game remains outside the specified v1 scope. The earlier PDF wording has been clarified toward this source-to-deck workflow. A downloadable PDF study report is an optional, open enhancement, not a required feature or permission to add a PDF dependency.
- Keep the original `next` requirement after each phase, the G0 design approval gate, and the human playtest gates after G1, G3, and the final release package. Do not infer approval from elapsed time or from the goal of eventually completing the game.
- Current workspace preparation is documentation only. No game feature has been implemented or tested by this register.
