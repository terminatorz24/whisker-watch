# Whisker Watch — canonical product requirements
Handoff revision: WW-HANDOFF-3. This document describes the product, not permission to start coding. Follow AGENTS.md and the access gate first.

## Product and scope
A fully functional browser tower-defense study game: original cat towers defend a Fish Stash from layered mice and rats. Strong BTD6 influence applies to the ENTIRE experience: strategic placement, recognizable tower classes, three-path upgrades, enemy layering/counters, targeting, abilities, maps, menus, visual hierarchy, outlines, shading and readable attack effects. Create original characters, scenery, route geometry and UI artwork; do not ship reference screenshots or extracted proprietary game assets.
Single player; no account, backend, in-game AI calls, telemetry, payments, sound or music. The owner may publish later, but publication requires explicit approval. All cats, upgrade paths and five maps are available from the start, constrained only by cost, placement and crosspath rules. No permanent unlock economy, mandatory achievements or mastery classification.

## Maps, modes and difficulty
Tutorial: Kitten Yard. Main maps: Sunny Backyard, Farmhouse Barn, Fish Market Docks, Frosty Rooftops, Cheese Moon. Each has distinct original paths, scenery, blocked/buildable areas and strategic choices; a recolor is not another map. Any structurally valid question deck can be used on any map.
Quick Run default: 40 waves; reduced bosses at 10/20/30/40. Full Campaign: 100 waves; bosses at 20/40/60/80/100. Easy/Normal/Hard change lives/costs/enemy speed according to configurable provisional values in docs/ECONOMY_MODEL.md. Difficulty does not switch question format. No endless mode required.

## Play loop
New Run or Load Save -> upload/paste JSON deck -> validation and optional editing -> map/mode/difficulty -> Study Break -> unlimited preparation -> manual Start Wave -> combat -> results -> next Study Break. The first wave also has questions.
Questions NEVER appear during active combat. No question countdown and no automatic between-wave countdown. Players may pause; buy/place/upgrade/sell/retarget cats and activate abilities during combat as well as prep. Existing towers cannot be moved for free. Selling returns the configured fraction of ACTUAL base-plus-upgrade payments; no sale/purchase cash exploit. Display the value before confirming. Enemies defeat/layer events pay cash immediately; a small clear-wave bonus exists. Lives decrease on leaks; game over and victory have a review/save/restart path. Speeds 1x/2x, with 3x optional, must not alter deterministic results.

## Towers and enemies
Baseline 16 cats: Dart, Yarn, Ice, Bomb, Blitz, Smash, Sniper, Night, Sky, Fire, Magic, Storm, Gadget, Scholar, Forest, Fisher. See docs/COMBAT_DESIGN_BRIEF.md for distinct roles, path directions and required design tables. Ricochet, Mortar and Harbor are optional candidates, not part of the baseline completion count; do not silently expand scope.
Each baseline type has 3 paths x 5 tiers = 240 real upgrades. A placed tower can use at most two paths, with one main path to tier 5 and the other to tier 2; all paths are unlocked. Every upgrade has explicit behavior, cost and visual feedback. First/Last/Close/Strong targeting and appropriate special targeting work consistently. Abilities show cooldowns. Scholar improves correct-answer earnings within caps; Fisher only enhances actual combat-derived income within caps. Neither replaces studying.
Layered mouse/rat chain with explicit children, speed, hit points, leak damage, defeat rewards and immunities. Include fast, Sneaky/detection, Regrow, Fortified, frost-resistant/explosion-resistant, Cheese-Armored and giant classes. No enemy should require an unavailable counter. Boss concepts: Matriarch Rat Queen (summons), Pied Piper (control/speed), Mecha Rat (shield/resistance), Rat Emperor (elite resurrection/defense targeting), Great Rat Overlord (combined threat). Their exact mechanics and numbers require completed design tables and tests, not inference from screenshots.
Each run length has an authored static wave table with defined introduction/counter checks. Do not silently generate new waves at runtime or directly copy another game's tables. Use original names/art and model the desired strategic experience.

## Studying and files
Only multiple-choice JSON is a playable study file. A learner gives a PDF, notes, test review or existing questions to an EXTERNAL AI with our copyable format prompt, then uploads the resulting .json file or pastes raw JSON. The game converts structure into UI; it does not create facts, verify truth or call an AI. Preserve the supplied answer key. A questionable answer is the deck author's responsibility, not a reason for structural rejection.
One deck needs at least ONE valid question. Recommend 20+ for Quick and 100+ for Full, but warn rather than block smaller decks. Repeat automatically across waves; do not require padding a 30-question source to 100 entries. Avoid within-break repeats when enough distinct questions exist. With fewer questions than the scheduled set, warn and use seeded repetition; question count/reward pool does not shrink. Duplicate IDs are errors; duplicate content with different IDs is accepted with a warning.
Use docs/DECK_FORMAT.md and its schema as the single format contract. Explanations are optional; empty/missing is accepted. Show supplied explanations without inventing new text. Track correct, incorrect, skips and exposure counts per stable question ID. Wrong answers earn zero; show the supplied correct answer. A capped correct-answer streak carries between waves and resets on wrong/skip. No mastery, timers affecting rewards, punitive slowdown or complex wager/retry system in the baseline.
Support preview/edit/add/remove/re-export and revised decks at safe between-wave boundaries. Preserve unchanged IDs and their statistics; explicitly explain resets/archives for changed questions. Raw correct/incorrect counts appear in reports. Export a study JSON deck with optional reviewStats beside each question; it remains re-importable. Imported reviewStats never mint run cash or pretend to be a full save.

## Economy
Question answering is the dominant funding source; combat cash enables emergency upgrades mid-wave. Question volume and cash budget are separate. Use docs/ECONOMY_MODEL.md for baseline formulas, cash/streak caps and reproducible income analysis. Those calculations do not prove combat viability. Balance from the REAL simulation at 0/60/80/95% accuracy, multiple strategies, both modes, all difficulties and all maps. Track power affordability and leaks per wave, not just cumulative money. A 0% strategy must not turn economic towers into an easy substitute for learning. Small decks may be easier to remember; no anti-cheating service is required.

## Exact save / resume is foundational
The downloadable JSON save embeds the active deck, learning statistics and complete authoritative run state. Upload/paste it, show a summary, resume paused, then continue at the saved point. Include tick, wave, mode/map/difficulty, cash/lives, towers/upgrades/payments/targeting/cooldowns, enemies/children, projectiles/hit history, traps/effects, spawns/events, entity IDs, question order/answer shuffle/current submission and reward receipts, independent RNG streams and exact balance/content identity.
Implement docs/SAVE_CONTRACT.md during the technical foundation BEFORE expanding combat. The FIRST playable slice must pass mid-wave and partially answered-study replay equivalence. Every added mechanic extends the schema and the regression suite. Do not leave serialization until the end. Saving is a consistent tick-boundary snapshot; a submitted answer never pays twice after reload.
Manual save files are authoritative. Show unsaved-progress warnings and save reminders; no automatic cloud account. Browser suspension pauses rather than advances the simulation unseen. No guarantee that closing a tab preserves unsaved play.

## Presentation and delivery
Colorful, dimensional cartoon art with strong outlines, mild shadows, recognizable cats/rat modifiers and visible upgrade changes. Static scenery; simple animated attacks, moving enemies/projectiles and restrained hit effects. Large playfield, readable top HUD, outside/collapsible right-hand cat shop, selected-cat three-path panel, placement ghost/range indicators and large multiple-choice buttons. Desktop Mac Chrome/Safari and mobile touch/iPhone Safari are targets. All interfaces and icons must be functional; reference stills are not production evidence.
Produce a style guide, base/tier-3/tier-5 cat sample, enemy modifier strip, gameplay HUD, study view and actual running-map screenshot for owner review before bulk artwork. Follow docs/ART_PIPELINE.md. After this bounded visual checkpoint, continue ordinary work independently.
Deliver a static HTTPS website with local development/preview instructions. A fully loaded session should continue without runtime network calls. Offline reopening/installable PWA and double-click file:// packages are NOT required for the first release; see docs/RUNTIME_DELIVERY.md. Hosting static files is not a data-processing backend. Do not publish before the owner approves.

## Completion
All five real maps + tutorial, both modes/difficulties, baseline cats/240 upgrades, bosses/counters, learning/import/editor/report flow, exact portable saves, original accepted artwork and automated/manual evidence must work. One map is an intermediate milestone, not completion. Use docs/IMPLEMENTATION_PLAN.md and docs/ACCEPTANCE_MATRIX.md. Missing future code is NOT IMPLEMENTED, not an access failure. A runnable app and its successful tests, not a long prompt, are the final deliverable.
